P44

Trace a ROS 2 robot command in simulation

A robot can receive a command and still return stale or absent feedback. Practise finding which process sent the command and which process received it in a software-only workspace.

Time 60–90 minutesBefore this P16 · P27 · T30
What you’ll use

A machine with the official ROS 2 Jazzy environment and turtlesim installed. Use the Jazzy install guide for a supported OS or a compatible VM. Run every shell example inside the simulation environment, with no physical robot or external command bridge.

Identify the camera, compute and motor-control layers

A robot publishes measurements through a running program or node. A named stream of messages is a topic. Another node subscribes to a command or data stream. The bench exercise uses a simulated turtle whose pose provides feedback.

Use the Jazzy install guide and the turtlesim tutorial. ROS 2 Jazzy installation · Official turtlesim exercise.

Prove a command and its observed result

Make three terminals in the simulation environment and source the Jazzy environment in each according to the platform’s install instructions. Start turtlesim in terminal A and keep it running.

ros2 run turtlesim turtlesim_node

In terminal B, discover the interfaces and watch feedback.

ros2 node list
    ros2 topic list -t
    ros2 topic info /turtle1/cmd_vel --verbose
    ros2 topic echo /turtle1/pose

In terminal C, run the keyboard teleop and use an arrow briefly. Return to terminal B to observe pose values. Stop the teleop and check that the command publisher disappears from the topic. Use Ctrl+C to stop your own CLI programs.

ros2 run turtlesim turtle_teleop_key

Watch on YouTube · Watch the simulated command and feedback. Compare the topics it uses with the commands in the Jazzy documentation. [ROS2 Q&A] 226 - Work with ROS2 turtlesim · The Construct Robotics Institute.

Diagnose a missing path

Use a fresh terminal with the Jazzy environment sourced, or interrupt the pose echo in terminal B. Run ros2 topic info /turtle1/cmd_vel --verbose before and while teleop runs. Then run ros2 topic info /turtle2/cmd_vel in the single-turtle simulation. A missing topic name is a different fault from publishing on a topic that has no matching subscriber. Compare exact namespace, type, endpoint count and QoS before suspecting the motor layer. A running pose stream can still repeat the same value for a stationary turtle.

A ROS topic is an interface between processes. Its health cannot establish that a real drive received usable electrical power. On real equipment, prove the stated boundary first, then move to the electrical layer under the applicable procedures.

Keep command and feedback evidence

Save node and topic lists, one pose before motion and another after motion. Keep the command path and feedback path named on a single diagram or worksheet. The official topics tutorial shows how to record rates and inspect individual message fields. ROS 2 Jazzy topics tutorial.
