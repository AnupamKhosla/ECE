Commission one complete air-handler sequence

Run a browser-based air-handler simulation, then prove a schedule, a fan, an alarm and a command priority using a timed functional test.

Time 60–90 minutesBefore this P29, P63, P79

Identify command, proof and permissive

An occupied schedule asks for ventilation. A safety permission must be healthy, and a fan command must lead to separate proof before this training sequence enables the temperature loop. Treat the scheduler as a request, the fan command as an output and fan proof as a separate input. A sensor failure is separate from a valid temperature out of range. This simplified classroom sequence uses fixed example delays and an example low limit; a real plant uses its approved sequence and independent safety circuits.

Write a functional test with pass criteria

  1. Start occupied with safety healthy. Advance 10 seconds. Expect fan command, proof and loop enable. Change to unoccupied, advance again, and expect all three off.
  2. Enable occupied, select missing fan proof and run three scans. Expect the alarm only on the third scan. Restore proof and check that the active alarm clears on the next scan. Log a real site’s required acknowledgement and latch behaviour separately.
  3. Return to normal proof. Try an operator stop while occupied. Release it and show that the schedule regains control. Then set operator start and remove the safety permission. Verify that the training safety veto wins. Restore the safe baseline and release the command.
  4. Start normally, switch the supply-air sensor to bad quality and advance. Expect proof with no loop enable. Try 4 °C with good quality and record what changes. Describe the signals and limits you would find in a real freeze-protection sequence before testing it.
