P160

Run and diagnose a ROS 2 joint trajectory

Run the two-joint profile from P159 through a real ROS 2 controller. Compare a valid goal, a wrong joint name and a mock interface that stops updating position. All three use software-only hardware.

Time 60–90 minutesBefore this P141 · P159

Start the controller and identify the feedback path

Use ROS 2 Jazzy on an isolated Ubuntu training system with no physical robot interfaces. Install the Jazzy controller manager, joint-state broadcaster, joint-trajectory controller, ROS 2 control CLI and robot state publisher packages for your installation. Save these three downloads to the same directory.

  • Robot description declares two joints and a software position interface for each.
  • Controller settings select the controllers, update rate and tolerances.
  • Launch file publishes the robot model and starts the manager.

Run the first command from that directory in a sourced Jazzy terminal. When the manager starts, run the spawner and observers in a second terminal from the same directory. Confirm both controllers become active and both position command interfaces are claimed.

ros2 launch "$PWD/trajectory_lab.launch.py"
ros2 run controller_manager spawner joint_state_broadcaster arm_controller \
  --param-file "$PWD/controllers.yaml"
ros2 control list_controllers
ros2 control list_hardware_interfaces
ros2 topic echo /joint_states --once

The position state comes from mock hardware. In the baseline the mock copies drive commands into position state. The joint-state broadcaster reports that state, and the trajectory controller compares state with its reference. A successful run establishes that these software connections and parameters work. Physical servo response, calibration, payload and collision clearance require other evidence. ROS 2 Control · Controller manager.

Prove the goal contract and execution

At startup the two joints read 0 rad. The goal moves them to about +90° and −30°. Both waypoint entries specify position, velocity and acceleration. With the default spline interpolator the 2.813 s zero-speed, zero-acceleration endpoints describe the quintic exercise. Joint names fix the order of the arrays. In another terminal, monitor controller state or add --feedback to the action command for a live trace.

ros2 topic echo /arm_controller/controller_state --field error.positions
ros2 action send_goal /arm_controller/follow_joint_trajectory \
  control_msgs/action/FollowJointTrajectory '
trajectory:
  joint_names: [joint_1, joint_2]
  points:
    - positions: [0.0, 0.0]
      velocities: [0.0, 0.0]
      accelerations: [0.0, 0.0]
      time_from_start: {sec: 0}
    - positions: [1.5708, -0.5236]
      velocities: [0.0, 0.0]
      accelerations: [0.0, 0.0]
      time_from_start: {sec: 2, nanosec: 813000000}'
  1. First send the goal with joint_typo in place of joint_2. Record the goal rejection and the normal controller state. Restore the correct name.
  2. Send the corrected goal from the known zero state. Keep the accepted response, a changing position sample, the successful result and both final positions.
  3. Close the first launch with Ctrl+C. Start it again with the argument freeze_feedback:=true. Spawn the controllers again and send the same valid goal once. The mock leaves positions at their starting values while the controller computes a changing reference.

Read the trajectory and goal tolerances under each joint in the YAML. An accepted goal can abort during the path. In the verified frozen run the controller returned ABORTED with error_code: -4, a path tolerance violation. The manager reported the configured URDF position and velocity limits. P159 checks acceleration and jerk in the planned profile separately. ROS 2 Control · Joint trajectory action and tolerances.

Compare the two measured runs

Download the measured controller feedback from the Jazzy mock runs. The observer recorded elapsed wall time from sending the goal and downsampled feedback to about five rows per second. Compare reference, feedback and error in radians at about 0.6 s. Explain why the last recorded frozen row can still be within the 0.12 rad limit when the action aborts.

Check the first failed boundary

The wrong name fails the controller’s goal contract before execution. In the accepted frozen case, joint 1 at about 0.60 s has a reference near 0.103 rad and feedback at zero. The controller checks error at its update rate. The observer samples less often, so a violation can occur between two retained rows. Confirm the action result and check message times and the feedback source before considering a tolerance change.
