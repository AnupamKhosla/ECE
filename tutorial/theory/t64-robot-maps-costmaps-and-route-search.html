Robot maps, costmaps and route search

A mobile robot stores the geometry it knows and the observations it has just received. Those layers answer different questions. Work through a mapped wall, a moving crate and a payload that changes which aisles the robot can use.

Time 50 minutesBefore this T59 · T63

Convert metres to map indices

An occupancy grid records whether cells are free, occupied or unknown according to the mapping convention. The map includes resolution in metres per cell, width and height in cells and an origin pose. Convert the position into the grid’s coordinate system by undoing that origin pose, including its rotation when present. Then divide coordinates by resolution and round down. A grid width of 100 cells uses index row × 100 + column in a row-major array.

Take a grid with zero origin rotation, origin (−2.0, −1.0) m and resolution 0.10 m. World position (−1.73, −0.74) m is (0.27, 0.26) m relative to the origin, so it occupies column 2 and row 2. The centre of that cell is world position (−1.75, −0.75) m. Check both bounds before indexing. An image file often counts rows down from the top, which matters when comparing image pixels with map data. ROS 2 · OccupancyGrid message layout.

Trace the observation that marked a cell

A range ray supplies evidence along a line in the sensor’s frame. A usable hit can mark its endpoint as occupied. Where configured, a valid clearing ray provides free evidence along the visible path. Cells behind the hit remain unobserved by that ray. A change in scan stamp helps establish freshness, and the matching transform places the ray onto the right part of the map. Each source has its own range limits, frame and marking or clearing rules.

A static map can provide walls and the approximate layout of a plant. A current obstacle layer can add a newly parked crate. The crate may stay in the layer until a valid later observation clears its location. Look for line of sight, scan delivery and transforms before deciding that a marked cell is a software bug. Check if a wall comes from the static layer, because clearing behavior and layer combination determine what appears in the combined map. Nav2 · Obstacle marking and clearing.

Work the aisle clearance before planning

A circular trainer with envelope diameter 0.42 m has 90 mm of physical clearance on each side when centred in a 0.60 m aisle. If position error can move the centre 40 mm toward the wall, 50 mm remains on that side before accounting for map discretization, wall survey error and control variation. A wider load can consume that margin. For a rectangular vehicle the footprint changes with yaw in the map, especially while turning through an entrance. Test the whole swept path at the maximum configured load.

An inflation layer adds cost around obstacles. A planner can prefer a wider path because accumulated traversal cost is lower, even when the shortest path is open. Lethal obstacle geometry, footprint collision and softer proximity penalties serve different purposes. The planning footprint, resolution and update rates still need verification in the operating environment. Nav2 · Inflation layer · Nav2 · Planning and footprint tuning.

Tell a route search from a tracking problem

In a four-connected training grid, A* scores a node by cost already incurred plus a lower-bound estimate of the remaining cost. Manhattan distance times the minimum cost of one step works for cardinal movement with no cheaper transitions. A successful search gives a series of cells. A real planner also has to account for the configured robot geometry and path constraints. A controller tries to follow the path while observing the current local costmap and vehicle motion.

  • If there is no route, check goal frame, map bounds and the relevant obstacle or footprint layer.
  • If a route exists but progress stops, compare near-field observations, velocity commands and odometry at matched times.
  • If a route passes through an apparently blocked aisle, look at when each costmap was updated, which frames were available and what footprint was active.

Navigation evidence helps diagnose the simulated task. Installed protective functions follow the validation process in T62.
