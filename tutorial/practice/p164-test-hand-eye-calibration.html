P164

Test a robot camera calibration on unseen poses

Recover a camera mount from projected board corners. Then swap two image-to-pose pairings and see how the robot-space error changes while the pixel error stays the same.

Time 55–75 minutesBefore this T67 · P143

Run a reproducible simulation

Download the calibration exercise and run it with Python 3, NumPy and OpenCV. Ubuntu 24.04 provides python3-opencv and python3-numpy. The measured examples below use OpenCV 4.6.0 and NumPy 1.26.4. No camera, robot or recorded images are required.

python3 calibrate.py --mount wrist
python3 calibrate.py --mount fixed
python3 calibrate.py --mount wrist --frames 4

The model has a 1280 × 1280 image, known intrinsics and distortion, and a 7 × 5 set of board corners spaced 28 mm apart. It projects those corners with projectPoints, adds Gaussian corner jitter of 0.16 px per component and calls solvePnP to obtain a camera-from-target pose. It uses the first 12 robot and camera pairs to fit the mount with OpenCV’s Park solver. The remaining six pairs stay out of the fit and preserve the true pairing in every run. OpenCV · Projection, pose estimation and hand-eye calibration.

Separate image error from station acceptance

For every held-out sample, reconstruct the stationary board in base coordinates for the wrist camera, or the tool board in tool coordinates for the fixed camera. Compare it with the known board transform in the simulator. Set an exercise limit of 5 mm translation and 0.50° rotation at each held-out pose. Keep the per-pose results even when the final line says PASS.

For the wrist run using one image per pose, find the pose that causes the hold. Repeat with four independently jittered images averaged at each preserved pose. Name the physical assumptions required to collect such a set at a station.

Compare the aligned runs

The wrist run has a maximum held-out shift of 3.07 mm and a maximum turn of 0.515° at pose 13, so it holds on angle. With four images those maxima are 1.29 mm and 0.373° and it passes. The fixed-camera run with one image passes at 2.85 mm and 0.347°. The simulator isolates independent corner jitter. Averaging assumes a stationary target and robot within each set. It leaves shared effects such as a wrong lens model or a shifted timestamp in place.

Replay two collection faults

python3 calibrate.py --mount wrist --scenario mismatched
python3 calibrate.py --mount wrist --scenario mismatched --frames 4
python3 calibrate.py --mount wrist --scenario single-axis

mismatched swaps two of the fitted camera poses after the image calculation. single-axis collects the fit set using only turns about a common axis. Its one-dimensional relative rotation check holds the run before fitting. The exercise uses the ratio of the second to first singular value of the relative rotation vectors and treats values below 0.05 as insufficient spread. That threshold belongs to this exercise and gives no general calibration guarantee.

What changes when two fit pairings are swapped?

The median fit-image residual is still 0.215 px in the one-image wrist run. Held-out translation grows from a maximum of 3.07 mm to 26.87 mm. Four images per pose reduce the image residual to 0.116 px and the mismatched run still has up to 25.85 mm of position error. Check image IDs, actual exposure timestamps and feedback sample identity before optimizing image precision.

Write a camera-mount acceptance record

Record which mount transform the station uses, its reference frames and its trigger-to-feedback pairing rule. Specify several independent witness points across the working volume and define an angular limit for the jaw or tool’s direction of approach. On a real station, use a separately surveyed reference or physical witness set to replace the simulator’s known geometry. Add a retest trigger for any adjustment to the camera, lens, tool frame or mount. Attach the pose-level evidence to the cell handover.
