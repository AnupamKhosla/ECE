Verify a Modbus register snapshot before using it

Two successful Modbus replies can assemble a position the device never published. Reproduce the rollover fault, then deliberately read one multi-register response during a source update and check what the application must validate.

Read the device map as a contract

The training position is a signed 32-bit number in micrometres. It occupies two contiguous holding registers, high word first. Function 03 reads 16-bit registers. The protocol defines high byte first within each word. The device map defines the order, signedness and scale of the combined value. A drawing that numbers the first holding register as 40001 corresponds to starting address zero in the request for this map. Modbus application protocol, section 6.3.

Run the real loopback transactions

Download CMakeLists.txt and modbus_snapshot.c to one writable directory. Use Linux with a C compiler, CMake, pkg-config and libmodbus. The program binds a temporary loopback port and includes its own read-only training client and server.

sudo apt install build-essential cmake pkg-config libmodbus-dev
cmake -S . -B build
cmake --build build
./build/modbus_snapshot > readings.csv

Both endpoints run in one process with separate TCP sockets. The server advances its simulated register map at specific request boundaries. This makes reading during an update repeatable without relying on operating system scheduling. Read the observed transaction decisions from libmodbus 3.1.10. libmodbus holding-register read API.

Match the protection to the device behavior

Read the epoch and version together as a stable pair, read both position words together, then re-read the pair. Accept after matching the expected epoch and verifying equal even versions. The writer must publish odd before changing the words and even after the complete value is visible. The guard assumes no complete version wrap between the metadata reads. With this 16-bit version and two increments per update, a stable number repeats after 32,768 publications. Bound the read interval and the publication rate. Recheck these assumptions whenever the mapping protocol changes.

Use an atomic device snapshot or latch if the vendor provides one. The client cannot invent an epoch or version guarantee absent from the device map. A coherent value can still be old, so keep the quality, age and source reconciliation checks as well. Record the raw words, scale, accepted version, epoch and elapsed poll time.

Why can grouping both words into a single Function 03 response still fail?

The response groups the words that the server supplies for that request. If the device application updates the high word before the low word and exposes the intermediate state, the reply contains an internally mixed value. Require a supported hold, snapshot or writer version contract.
