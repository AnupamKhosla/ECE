P122

Protect laptop data and run a repeatable handover test

Separate diagnosis from destructive work, record owner authorization and deliver acceptance tests for storage, firmware, repairs and peripherals.

Time 40–60 minutesBefore this P116, P117

Record who owns the data and what the job allows

Run this first as a mock intake on your own laptop, using disposable test files. Write the customer symptom in their words, and separately record exact model, power input, owner’s data priority, available backup and allowed operations. Ask the owner to use the manufacturer’s supported unlock or enrollment procedure themselves. Never store a password, recovery key or account code in a bench ticket. An organization’s system needs its administrator’s authorised workflow.

Review boot configuration, storage detection and signs of data-risk before changes. Get explicit scope for initialization, a reset, reinstall, disk writes, major board changes that affect storage, or a destructive firmware restore. A known-good backup includes a test restore or verification of representative files. Keep a failing drive out of stress tests while the owner decides the priority of recovery. Compare the options in P93 · Qualify a used SATA or NVMe SSD without reading files and T50 · Inside SSDs: flash wear, spare blocks and health reports.

See how to read storage health information as one part of a repair record.

Use a handover sheet that proves the specific repair

  1. Record one reproducible pre-repair failure and how it was observed. Note conditions such as charger, outlet, access state, boot device, display or dock.
  2. After repair, repeat the same test twice. Confirm two cold boots, charging and battery discharge, expected sleep/wake, display and input, and any adjacent port, audio or Wi-Fi path that was disturbed. Run stress checks on appropriate known-good hardware with temperature and shutdown limits.
  3. Compare detected storage, memory and battery to intake. Record diagnostic results without identifiers or contents that the owner has not agreed to share. List the exact part fitted, any model-specific calibration, unresolved symptoms and data outcome.

Write a two-sentence handover for a mock customer. State what failed, why the observed result supports it and what checks passed. Include one condition you could not reproduce. Continue to C16 · Build a repair portfolio and a shop workflow for portfolio examples without customer data.
