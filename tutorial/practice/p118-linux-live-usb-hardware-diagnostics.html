P118

Use a Linux live USB to isolate a laptop hardware fault

Compare the same peripheral across installed and live systems, then collect readable kernel evidence without writing to the internal drive.

Time 50–80 minutesBefore this P19, P116

Boot a test environment and protect the original storage

Use an owned x86-64 practice laptop, an empty removable USB and an official matching Ubuntu image. The image writer overwrites the selected removable drive. Match its size and device before selecting it, and unplug other removable storage. Use the machine’s one-time boot menu, choose Try Ubuntu, and leave internal partitions unopened. Follow Canonical’s exact instructions. On ARM or Apple silicon use a separate platform-specific path. Do not disable encryption or change firmware settings to make the comparison work.

Watch a live USB boot and the Try Ubuntu option. Use Canonical’s current guide for the exact screens.

Observe the hardware from two environments

  1. Write down one symptom, e.g. a USB mouse disconnects intermittently. Compare the same known-good mouse, port, workload and fault trigger in the installed system and the live session. Use a second known-working port as the control.
  2. In the live terminal run lsusb before and after connection and lspci -nn for PCI devices. Use lsblk -o NAME,MODEL,SIZE,TRAN,TYPE to identify visible devices without mounting them. Use journalctl -k -b --no-pager or permitted kernel logs around the event. A retired practice laptop can be tested without a customer disk fitted.
  3. Record device ID, port and event time, and compare only relevant lines. An error in both operating systems with matching conditions increases suspicion of the path shared by both. Missing Wi-Fi in the live image alone may reflect kernel or firmware support. Test with a known-good device and an OS supported on this model.

Repeat a resume fault with one change

Record kernel version with uname -r, supported states using cat /sys/power/mem_sleep where present, plus whether AC power or a dock was attached. Compare two suspend and resume cycles with the dock removed. Live-session logs usually disappear at power-off. Save only the relevant redacted evidence externally. Restart without the USB and verify the original boot path. Continue with P121 · Isolate laptop port, headphone and speaker faults if a physical connector or modular port is implicated.
