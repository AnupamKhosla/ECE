T30

Firmware timing, state machines and recovery

Describe what a controller should do in every state, including at startup, on loss of input and when the main loop takes longer than expected.

Prerequisites T15, T16Bench P27, P30

Events, state and timing

A state machine has a state, an input or event, and conditions that select the next state. Outputs can be mapped directly from state. A three-state controller can start in idle, enter running after a command, and move to fault on timeout. Give stop or fault conditions explicit priority when two events happen together. Write a state table before coding so every expected transition has a bench test.

For a 32-bit millisecond counter, rollover occurs after 232 ms, about 49.7 days. For a short interval and regularly evaluated timers, compare an unsigned elapsed time now - started with the interval. Unsigned subtraction wraps consistently. For example, 0x0000000A − 0xFFFFFFF0 is 26 ticks modulo 232. Long blocking calls delay checks even when the arithmetic is correct. Arduino’s non-blocking timing example.

Debounce, schedule and recover

A switch can bounce between levels for several milliseconds. Record the time of the last raw edge, then accept the new stable state once it has held long enough. Trigger from the accepted edge so a held button cannot continually reissue a one-shot command. Choose whether an input needs an immediate fail-off path or can wait through debounce. A training software stop is different from a rated physical safety stop.

A watchdog resets a controller if healthy execution stops servicing it. A brownout detector resets on an inadequate supply. Decide what happens after either reset and keep outputs in a defined state during pin startup. External pull resistors can hold a driver disabled until the firmware is ready. Telemetry and display work should have bounded time so control keeps running. Arduino debounce example and circuit.

Check yourself

A button drives a five-second output. What happens if the button is held for 20 seconds?

In an edge-triggered design the output runs once and returns to idle at timeout. A second command requires a release and a new press. Verify it at the bench as an explicit test.
