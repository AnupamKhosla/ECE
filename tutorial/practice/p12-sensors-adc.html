Sensors and the ADC

Turn light, temperature, motion and distance into numbers. You will learn exactly how the Arduino's analogue-to-digital converter (ADC) turns a voltage into a count, read five kinds of temperature sensor including the 10 kΩ NTC thermistor used in building sensors, and make readings steady and accurate with averaging and calibration.

How the ADC turns volts into a number

Sensors give you a voltage. The microcontroller only understands numbers. The analogue-to-digital converter (ADC) is the circuit in between. The Uno's ADC is 10-bit: it divides the range from 0 V to a reference voltage (normally the 5 V supply) into 210 = 1024 equal steps, and tells you which step the input is on, as a whole number from 0 to 1023.

step size (1 LSB) = Vref / 1024 = 5.000 / 1024 ≈ 4.88 mV "LSB" means least significant bit: the smallest change the ADC can see. With a 5 V reference, any change smaller than about 4.9 mV is invisible.
reading = floor( Vin × 1024 / Vref )    and back:    Vin ≈ reading × Vref / 1024 Worked example: Vin = 1.250 V → 1.250 × 1024 / 5 = 256. Reading 256 → 256 × 5 / 1024 = 1.250 V. You will see code that divides by 1023 instead; the difference is 0.1%, much smaller than the error in your "5 V" supply.

Inside, the Uno uses a successive-approximation ADC. It first grabs the input voltage on a tiny capacitor (sample-and-hold), then plays "higher or lower" with an internal digital-to-analogue converter: is it above half of Vref? Above three-quarters? Ten yes/no questions find one of 1024 levels. One analogRead() takes about 100 µs, so you can read about 10 000 times per second.

First sketch: read a voltage

Put a 10 kΩ potentiometer between 5 V and GND with its wiper on A0, or just use two 10 kΩ resistors as a divider (P04). Measure the A0 voltage with your meter and compare it with what the Arduino reports.

const int SENSOR_PIN = A0;      // analogue input 0
const float VREF = 5.0;         // measure your board's 5V pin and put the real value here

void setup() {
  Serial.begin(9600);           // open the Serial Monitor at 9600 baud
}

void loop() {
  int reading = analogRead(SENSOR_PIN);     // 0..1023
  float volts = reading * VREF / 1024.0;    // convert the count back into volts
  Serial.print("reading=");
  Serial.print(reading);
  Serial.print("  volts=");
  Serial.println(volts, 3);                 // 3 decimal places
  delay(250);                               // 4 lines per second
}
Bench tip

On USB power the Uno's "5 V" is often 4.7–5.1 V, depending on the cable and port. Since the ADC measures relative to that rail, your volts are off by the same percentage. Measure the 5V pin with your meter and put the real number in VREF. Better still, use ratiometric sensors (dividers powered from the same 5 V): then the supply error cancels out, as you will see with the LDR and the thermistor.

Light: the LDR voltage divider

An LDR (light-dependent resistor, or photoresistor) is a strip of cadmium sulphide. Light frees extra electrons in it, so its resistance falls as light increases: very roughly a few kΩ in a bright room, tens of kΩ in dim light, and around a megohm in darkness. The exact values vary a lot from part to part.

The ADC measures voltage, not resistance. So you put the LDR in a voltage divider with a fixed resistor. With the LDR on top (to 5 V) and 10 kΩ on the bottom (to GND), more light gives a higher voltage.

Notice that 10 kΩ gives the most change around 10 kΩ of LDR resistance. A good rule: choose the fixed resistor close to the sensor's resistance in the middle of the range you care about.

const int LDR_PIN = A0;            // LDR divider output
const int LED_PIN = 8;             // LED + 220 Ω from P11
const int DARK_ON = 300;           // below this reading, turn the light on
const int DARK_OFF = 350;          // above this, turn it off (a gap stops flicker)
bool lampOn = false;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int light = analogRead(LDR_PIN);           // bigger number = brighter
  if (!lampOn && light < DARK_ON) lampOn = true;    // getting dark: switch on
  if (lampOn && light > DARK_OFF) lampOn = false;   // clearly light again: switch off
  digitalWrite(LED_PIN, lampOn ? HIGH : LOW);
  Serial.println(light);                     // open Tools › Serial Plotter to see a graph
  delay(100);
}
Why the gap between 300 and 350?

That gap is called hysteresis. With a single threshold, a reading that hovers around it (plus noise) would switch the lamp on and off many times per second. With two thresholds, the reading must move clearly past the other one to change state. Every thermostat and every BMS on/off control uses this idea, often called a "deadband" or "differential".

Bench tip

The Uno's ADC works best when the source resistance is 10 kΩ or less, because its sample capacitor must charge in a few microseconds. A divider made of 1 MΩ resistors gives readings that are slightly wrong and that "leak" from the previous channel. If you must use high resistances, read the channel twice and throw away the first reading, or put 100 nF from the pin to GND.

TMP36: an analogue voltage

Inside the TMP36, the voltage across a silicon junction changes by about −2 mV/°C (you met this in the diode chapters). The chip amplifies that into a neat output: 0.500 V at 0 °C, plus 10 mV per °C. So 25 °C gives 0.750 V.

T(°C) = (Vout − 0.500) × 100 Example: analogRead returns 154 with a 5.00 V reference. V = 154 × 5 / 1024 = 0.752 V. T = (0.752 − 0.500) × 100 = 25.2 °C. One ADC step (4.88 mV) is about 0.5 °C, so the reading jumps in half-degree steps.
const int TMP_PIN = A0;
const float VREF = 5.0;               // your measured 5 V value

void setup() {
  Serial.begin(9600);
}

void loop() {
  long sum = 0;
  for (int i = 0; i < 16; i++) {      // take 16 readings...
    sum += analogRead(TMP_PIN);
    delay(2);
  }
  float reading = sum / 16.0;         // ...and average them (keeps fractions of a step)
  float volts = reading * VREF / 1024.0;
  float tempC = (volts - 0.5) * 100.0;    // TMP36: 0.5 V at 0 °C, 10 mV per °C
  Serial.print(volts, 3);
  Serial.print(" V   ");
  Serial.print(tempC, 1);
  Serial.println(" C");
  delay(500);
}
Try this

Add analogReference(INTERNAL); in setup() and change VREF to 1.1. The step becomes 1.1/1024 ≈ 1.07 mV ≈ 0.1 °C, five times finer. The internal reference is only roughly 1.1 V (it varies by chip), so calibrate against a known temperature. Range is limited to 1.1 V, which is 60 °C for a TMP36. Remove the line before using A0 for 0–5 V signals again.

DS18B20: a digital sensor on a 1-Wire bus

The DS18B20 contains its own ADC. It sends the temperature as a number over a 1-Wire bus: one data wire plus ground, with a 4.7 kΩ pull-up resistor (the same pull-up idea as P11, because the sensor only ever pulls the line low). Every DS18B20 has a unique 64-bit serial number, so you can put many sensors on one pair of wires and read each one by address. Long cables do not add analogue error, because the data is digital.

Install two libraries from Tools › Manage Libraries: OneWire and DallasTemperature.

#include <OneWire.h>              // low-level 1-Wire timing
#include <DallasTemperature.h>     // DS18B20 commands on top of it

const int ONE_WIRE_PIN = 4;          // DQ on D4, with 4.7 kΩ from D4 to 5 V
OneWire oneWire(ONE_WIRE_PIN);       // create the bus on that pin
DallasTemperature sensors(&oneWire); // give the bus to the temperature library

void setup() {
  Serial.begin(9600);
  sensors.begin();                   // search the bus for sensors
  Serial.print("Sensors found: ");
  Serial.println(sensors.getDeviceCount());
}

void loop() {
  sensors.requestTemperatures();     // all sensors measure now (up to 750 ms at 12-bit)
  float t = sensors.getTempCByIndex(0);   // read the first sensor found
  if (t == DEVICE_DISCONNECTED_C) {  // the library returns -127 when nothing answers
    Serial.println("Sensor not responding: check wiring and the 4.7k pull-up");
  } else {
    Serial.print(t, 2);
    Serial.println(" C");
  }
  delay(1000);
}

DHT22: temperature plus humidity

The DHT22 (also sold as AM2302) measures temperature and relative humidity (RH). It uses its own one-wire-style timing protocol, which is not the same as Dallas 1-Wire. It is slow: read it no more than once every 2 seconds. Modules on a small board usually already include the pull-up resistor; a bare 4-pin sensor needs 10 kΩ from data to 5 V. Install the DHT sensor library (by Adafruit) and accept its dependency.

#include <DHT.h>

const int DHT_PIN = 7;               // module "out" or "data" pin on D7
DHT dht(DHT_PIN, DHT22);             // tell the library which pin and which sensor type

void setup() {
  Serial.begin(9600);
  dht.begin();
}

void loop() {
  delay(2000);                       // the DHT22 needs at least 2 s between readings
  float h = dht.readHumidity();      // % relative humidity
  float t = dht.readTemperature();   // degrees Celsius
  if (isnan(h) || isnan(t)) {        // NaN = "not a number": the read failed
    Serial.println("DHT read failed");
    return;                          // skip the rest of this loop() pass
  }
  Serial.print(t, 1);
  Serial.print(" C   ");
  Serial.print(h, 1);
  Serial.println(" %RH");
}

The 10 kΩ NTC thermistor: the BMS workhorse

Open a typical room temperature sensor on a commercial building wall and you will often find a single small bead: an NTC thermistor. NTC means negative temperature coefficient: its resistance falls as it warms. It is cheap, tough and needs only two wires. The building controller measures its resistance and converts that to a temperature using the thermistor's curve.

Why does resistance fall? A thermistor is a semiconductor (a metal-oxide ceramic). Heat frees more charge carriers, and more carriers means less resistance. That is the opposite of a metal wire, where heat makes atoms vibrate more and resistance rises.

The Beta equation

Over a moderate range, an NTC follows the Beta equation well. You need three numbers from the datasheet: R0 (resistance at the reference temperature, 10 kΩ), T0 (the reference temperature, 25 °C = 298.15 K) and β (Beta, the curve's steepness, often 3950 or 3435 for hobby parts).

1/T = 1/T0 + (1/β) × ln(R / R0)     (T in kelvin) ln is the natural logarithm. Temperatures must be in kelvin: K = °C + 273.15. The equation comes from the physics of carriers being freed by heat (an exponential, like the diode equation).

Worked example. The thermistor is the bottom half of a divider with a 10 kΩ fixed resistor on top (to 5 V), and analogRead gives 341.

  1. Find the resistance. The divider gives reading/1024 = R/(Rfixed + R). Solve for R: R = Rfixed × reading / (1024 − reading) = 10 000 × 341 / 683 ≈ 4 993 Ω. The 5 V value does not appear anywhere: the measurement is ratiometric, so supply errors cancel.
  2. Take the log. ln(4993 / 10 000) = ln(0.4993) ≈ −0.6946.
  3. Divide by β. −0.6946 / 3950 ≈ −0.0001759.
  4. Add 1/T0. 1/298.15 = 0.0033540. Sum = 0.0031782 K−1.
  5. Invert. T = 1 / 0.0031782 ≈ 314.6 K → 314.6 − 273.15 = 41.5 °C.

Check: a reading of 512 gives R = 10 000 × 512/512 = 10 kΩ, ln(1) = 0, so T = T0 = 25.0 °C. Exactly half the supply means exactly R0.

The Steinhart–Hart equation

The Beta equation assumes the curve has the same "steepness" everywhere. Real thermistors drift from that by a few tenths of a degree across a wide range. The Steinhart–Hart equation adds terms to follow the real curve closely, typically within about 0.1 °C over a wide range:

1/T = A + B·ln(R) + C·(ln R)3 A, B and C come from the manufacturer, or you calculate them by measuring R at three known temperatures (for example an ice bath at 0 °C, a room reading against a trusted thermometer, and warm water at about 50 °C) and solving three equations. Building controllers usually store the full curve as a table for each thermistor "type".
const int NTC_PIN = A1;
const float R_FIXED = 10000.0;    // fixed resistor from 5 V to A1 (measure it for best accuracy)
const float R0 = 10000.0;         // thermistor resistance at 25 °C
const float T0 = 298.15;          // 25 °C in kelvin
const float BETA = 3950.0;        // from the thermistor datasheet

void setup() {
  Serial.begin(9600);
}

void loop() {
  long sum = 0;
  for (int i = 0; i < 32; i++) sum += analogRead(NTC_PIN);   // average 32 readings
  float reading = sum / 32.0;

  if (reading < 1 || reading > 1022) {          // pinned at a rail: wiring fault
    Serial.println(reading < 1 ? "Sensor SHORT" : "Sensor OPEN");
  } else {
    float r = R_FIXED * reading / (1024.0 - reading);  // divider: resistance of the NTC
    float invT = 1.0 / T0 + log(r / R0) / BETA;        // Beta equation (log() = natural log)
    float tempC = 1.0 / invT - 273.15;                 // kelvin to Celsius
    Serial.print("R=");
    Serial.print(r, 0);
    Serial.print(" ohm   T=");
    Serial.print(tempC, 2);
    Serial.println(" C");
  }
  delay(1000);
}

On the job

On a BMS site you configure each analogue input (AI) for the sensor type: for example "10K Type 2" or "10K Type 3" thermistor, a 20K NTC, or a PT1000 RTD (a platinum resistor that rises with temperature). These names describe different R–T curves. If the controller expects one curve and the sensor follows another, the reading is wrong by a few degrees, which looks like a "calibration" fault but is a configuration fault. The field check: disconnect the sensor at the controller, measure its resistance with your meter, and compare with the manufacturer's table at the room temperature shown by a trusted thermometer. An open NTC reads as extremely cold (infinite resistance) and a shorted one as extremely hot. Many controllers flag both as a sensor fault, exactly like the sketch above.

Common misconception

"Higher resolution means higher accuracy." No. Resolution is the smallest step the system can show. Accuracy is how close the reading is to the truth. A 12-bit ADC with a ±5% reference and a ±1 °C thermistor still gives a reading that can be a degree out, displayed to two decimal places. Displaying 23.47 °C does not make it true; calibration does.

Motion: the PIR sensor

A PIR (passive infrared) sensor sees changes in heat radiation. Your body at about 37 °C radiates infrared light at wavelengths around 10 µm. "Passive" means the sensor sends nothing out; it only receives.

Inside the metal can are two pyroelectric elements: crystals that produce a small charge when their temperature changes. They are wired in opposition, so a slow change that heats both equally (the sun moving, the room warming) cancels out. The white plastic dome is a Fresnel lens array: it splits the room into many narrow zones. When a warm body crosses from one zone to the next, first one element and then the other sees it, and the output swings positive then negative. The module's chip detects that swing and sets its output HIGH.

The common HC-SR501-type module runs from about 5–20 V and gives a 3.3 V HIGH output, which an Uno reads as HIGH. It has two trimmer potentiometers (sensitivity and on-time) and usually a jumper for single trigger or repeat trigger mode. After power-up it needs roughly 30–60 seconds to settle; ignore its output during that time.

const int PIR_PIN = 3;               // PIR module OUT
const int LED_PIN = 8;
int lastMotion = LOW;

void setup() {
  pinMode(PIR_PIN, INPUT);           // the module drives the line; no pull-up needed
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);
  Serial.println("PIR warming up (60 s)...");
  delay(60000);                      // a blocking wait is fine here: nothing else to do yet
  Serial.println("Ready");
}

void loop() {
  int motion = digitalRead(PIR_PIN);
  digitalWrite(LED_PIN, motion);     // LED follows the PIR output
  if (motion == HIGH && lastMotion == LOW) {     // rising edge: motion just started
    Serial.print("Motion at ");
    Serial.print(millis() / 1000);
    Serial.println(" s");
  }
  lastMotion = motion;
}
On the job

The PIR detectors on alarm systems use exactly this physics: dual (or quad) pyroelectric elements and a Fresnel or mirror optic. A commercial detector adds a relay output (normally closed, opening on alarm), a tamper switch, and terminals for end-of-line resistors so the panel can supervise the cable. "Dual-tech" detectors add a microwave sensor and alarm only when both agree, which cuts false alarms from heaters and sunlight. When an installer says "don't point a PIR at a window or a heater duct", you now know why: those are fast heat changes that look like a person. Lighting occupancy sensors in offices are PIRs too.

Distance: the HC-SR04 ultrasonic sensor

The HC-SR04 is a tiny sonar. You send a 10 µs pulse to its TRIG pin. It fires eight pulses of 40 kHz ultrasound (far above human hearing), then sets its ECHO pin HIGH until the echo comes back. The echo pulse width is the round-trip travel time.

distance = (echo time × speed of sound) / 2 Speed of sound in air ≈ 343 m/s at 20 °C = 0.0343 cm/µs. Divide by 2 because the sound goes there and back. Example: echo = 5830 µs → 5830 × 0.0343 / 2 ≈ 100 cm. Shortcut: cm ≈ µs / 58.
const int TRIG_PIN = 9;
const int ECHO_PIN = 10;

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  Serial.begin(9600);
}

void loop() {
  digitalWrite(TRIG_PIN, LOW);         // make sure TRIG starts low
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);        // 10 µs trigger pulse
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  // Measure how long ECHO stays HIGH, in µs. Give up after 30 000 µs (about 5 m).
  unsigned long us = pulseIn(ECHO_PIN, HIGH, 30000UL);
  if (us == 0) {
    Serial.println("No echo (out of range or no target)");
  } else {
    float cm = us * 0.0343 / 2.0;      // 0.0343 cm per µs, halved for the round trip
    Serial.print(cm, 1);
    Serial.println(" cm");
  }
  delay(100);                          // wait for old echoes to die away
}

The speed of sound changes with air temperature: roughly c ≈ 331.3 + 0.606 × T(°C) m/s. At 35 °C (a hot Australian plant room) it is about 352.5 m/s, 2.7% faster than at 20 °C, so an uncorrected reading of 2.00 m is really about 2.05 m. If you have a temperature sensor on the same board, use it to correct.

Bench tip

Soft materials (curtains, clothing) absorb ultrasound, and surfaces at an angle reflect it away, giving "no echo". Aim straight at a flat, hard target for testing. Industrial ultrasonic level sensors on water tanks work on the same principle with better transducers and temperature compensation.

Calibration and averaging

Averaging cuts random noise

Every reading has a little random noise: a step or two of jitter from the supply, the ADC and the wiring. If the noise is random, averaging N readings reduces it by a factor of √N. Sixteen readings give four times less noise; 64 give eight times less. Averaging also gives you fractions of a step, which is why the TMP36 sketch above averages 16 readings.

MethodGood forCost
Block average (sum N, divide by N)Steady signals, simpleN readings per result
Exponential moving average: f += a*(x - f)Continuous smoothing, one reading at a timeSlower response; a = 0.1 means about 10 readings of "memory"
Median of 5Rejecting single spikes (e.g. one bad ultrasonic echo)Sorting 5 numbers
float smooth = 0;                    // filtered value, kept between loop() passes
bool first = true;

float readSmoothed(int pin) {
  int x = analogRead(pin);
  if (first) { smooth = x; first = false; }   // start the filter at the first reading
  smooth += 0.1 * (x - smooth);      // move 10% of the way towards each new reading
  return smooth;
}

int median5(int a[5]) {              // sort a copy of 5 values and return the middle one
  int b[5];
  for (int i = 0; i < 5; i++) b[i] = a[i];
  for (int i = 0; i < 4; i++)        // simple bubble sort is fine for 5 items
    for (int j = 0; j < 4 - i; j++)
      if (b[j] > b[j + 1]) { int t = b[j]; b[j] = b[j + 1]; b[j + 1] = t; }
  return b[2];                       // the middle value ignores one high and one low spike
}

Two-point calibration fixes offset and gain

Averaging removes random noise. It does not remove a systematic error, for example a sensor that always reads 1 °C high. For that, compare with a trusted reference at two points and correct both the offset (a fixed shift) and the gain (a slope error).

corrected = ref1 + (raw − raw1) × (ref2 − ref1) / (raw2 − raw1) Worked example: in an ice-water bath (true 0.0 °C) your sensor reads 1.2 °C. In a room where a trusted thermometer says 25.0 °C, it reads 26.1 °C. Gain = 25.0 / (26.1 − 1.2) = 1.004. A raw reading of 30.0 °C becomes 0 + (30.0 − 1.2) × 1.004 = 28.9 °C.
Safety and care

For an ice bath use a waterproof DS18B20 probe or seal the sensor in a thin plastic bag; never put the Arduino or bare wires in water. Everything in this lab runs on 5 V from USB, which is extra-low voltage. Some PIR and sensor modules are sold for mains-powered lighting: do not wire anything to 230 V. Mains work in Australia is for licensed electricians only.

Check yourself

An Uno with a 5.00 V reference returns 600. What is the input voltage?

V = 600 × 5.00 / 1024 ≈ 2.930 V. The true value is somewhere between 2.930 V and 2.935 V, because one step is 4.88 mV.

Why is the NTC divider calculation independent of the exact 5 V supply?

The divider output is 5 V × Rntc/(Rfixed + Rntc) and the ADC compares it with the same 5 V. The reading is therefore 1024 × Rntc/(Rfixed + Rntc): the supply voltage cancels. This is called a ratiometric measurement.

A BMS room sensor suddenly reads −40 °C. What is the most likely fault?

An open circuit: a broken wire, a loose terminal or a failed thermistor. Open means infinite resistance, and for an NTC very high resistance means very cold. A short would read very hot instead. Check terminations, then measure the sensor's resistance.

A TMP36 gives 0.68 V. What temperature is that?

(0.68 − 0.50) × 100 = 18 °C.

You average 64 readings. By how much does random noise fall?

By √64 = 8 times. Averaging does not fix a constant offset or gain error; that needs calibration.

An HC-SR04 echo pulse is 1160 µs. How far away is the target (20 °C)?

1160 × 0.0343 / 2 ≈ 19.9 cm (or 1160 / 58 = 20 cm).

Why does a PIR not detect a person who stands completely still?

Pyroelectric elements respond to changes in temperature, not to temperature itself. With two elements wired in opposition and a lens splitting the view into zones, only movement between zones produces the plus-minus signal. A still person gives a constant input that the sensor ignores.

Why connect the HC-SR04's ECHO to an ESP32 through a 1 kΩ / 2 kΩ divider?

ECHO swings to 5 V. ESP32 inputs are 3.3 V and not rated for 5 V. The divider gives 5 × 2/(1 + 2) = 3.33 V, which reads HIGH safely.
