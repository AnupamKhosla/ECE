P161

Compile and replay a PLC robot station

Turn the PLC handshake into a Structured Text function block. Step through a job at controlled scan times, then prove that an old result, a late acknowledgment and a lost link cannot create an extra good part.

Time 60 minutes with the trace or 100 minutes with compilationBefore this P144 · T30 · T34

Watch. Follow a physical input through to its ladder contact. Then check which handshake state owns the output. RealPars · Convert a wiring diagram to a PLC program.

Give each signal a single owner

This software-only lab processes input images. A call reads one set of simulated inputs and produces one resulting state. The C replay supplies clock values and selected scan images. There are no physical outputs. Structured Text is one of the PLC languages specified by IEC 61131-3. IEC 61131-3 · Programming language scope.

A link-loss input tells the sequencer that its remote evidence is no longer current. The lab treats it as an ordinary process condition. The installation’s protective functions and recovery procedures are separate work. T62 · Safeguard validation.

Read the output of the actual replay

Download the verified scan trace. Work from the columns interface_job_id, last_issued_id and last_committed_id. The first is meaningful for a request or acknowledgment when its associated flag is set. A last-issued ID is history and does not prove a part was placed.

  1. In complete, compare 260 ms with 270 ms. The station started waiting at 20 ms. The matching acknowledgment at elapsed 250 ms qualifies because the policy accepts it on the deadline scan. In late_ack, the deadline scan has no qualifying acknowledgment and the next scan remains held.
  2. Find when the good count changes. Explain why a good result at 510 ms gives zero parts, and why the count stays at one while the result is repeated. Inspect the renewed consumption acknowledgment after the link returns at 570 ms.
  3. In missing_proof, explain why job 42’s good result plus job 41’s proof records zero. In wrap_and_loss, compute elapsed time across the 32-bit clock wrap and explain why the link fault takes priority over a matching result and proof.
  4. In boot_and_rearm, identify the observations that allow a fresh review and start. The two edge memories initialize to the held state, which requires seeing each button released before accepting its first press.
Check the rollover and loss decisions

The acknowledgment at clock value 209 follows the request at 4,294,967,255 by 250 ms. From the request until the clock reaches zero takes 41 ms. Add 209 ms after zero. At value 219 the link is unhealthy, so the block enters review, cancels request output and records no new part. A new sequence must wait for a fresh review of actual disposition.

Translate the Structured Text and run it

Save station.st and replay.c to the same writable training directory. Build the open-source MatIEC compiler in a separate writable training directory using its build instructions. This replay was verified against commit c316fe57e335381cbe91f61c7366857198580ac7. The harness uses that emitter’s generated C declarations. Pinned MatIEC source · Beremiz · Build MatIEC.

In the lab directory set MATIEC to the path of the built compiler’s source directory. Run each command and check the first error if a step fails. The replay executes the generated IEC function-block code, using the C program as a clock and input adapter.

MATIEC=/absolute/path/to/built/matiec
mkdir -p generated
"$MATIEC/iec2c" -I "$MATIEC/lib" -T generated station.st
cc -std=gnu11 -O2 -I generated -I "$MATIEC/lib/C" replay.c -lm -o generated/station-replay
./generated/station-replay > generated/replay.csv

Plan the first real recovery evidence

Within a running instance the count persists through simulated link loss. A process restart resets the training block and starts in review. A deployed station needs tested rules for record retention, uniquely identifying a job across reboots and reconciling actual part location with retained records. A production counter and a separate remote write can fail between updates. In your acceptance plan say who owns the durable record, how a repeated job is detected and which physical proof lets the next part proceed.
