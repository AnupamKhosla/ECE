P171

Rehearse a robot cell restore before handover

A training station loses its main computer after the backup. Restore to a clean folder, verify the commissioned setup and bring the production journal up to its independent latest record.

Time 60–85 minBefore this P162 · Station journal · T72 · Cell recovery

Gather the packet and commissioning record

Use Python 3 with the standard SQLite module and a local writable directory. Put restore_drill.py, journal.py, station-events.csv and post-backup-events.csv in the same directory. The exercise creates only simulated files in a new directory. Run with a fresh name for each attempt.

python3 restore_drill.py run-01 station-events.csv post-backup-events.csv > restore-log.csv
python3 journal.py report run-01/restored/journal.sqlite

The release record expects CELL4-R12, PLC program PLC-P09, robot program ROBOT-P14, fixture FIXTURE-V3 and camera transform CAM-CELL4-FIXTURE3-C17. These are fixed in the teaching script as if they came from a commissioning sign-off. The independent production record expects PART-042 and PART-043 through event robot-205 at backup. It expects PART-044 as well through robot-206 afterward.

The deliberately incomplete copy is made with the source connection still open. The first good part was checkpointed to the main file, while later commits still sit in the WAL. The supported snapshot captures those later committed records. The exercise matches the last recorded event ID and the exact set of good serials, because matching counts alone would accept a swapped serial. Observed restore decisions · SQLite backup operation.

Use the restore evidence in service

  1. Open the restored report and find PART-044. Match its robot, placement and inspection evidence to the separate event suffix. Inspect the job still held for repeating PART-042.
  2. Remove the final robot event from a copy of post-backup-events.csv. Repeat in another new directory. Record which assertion fails, the missing evidence and who owns checking the fixture and physical part. Never invent a completion receipt to fit a counter.
  3. Draft the first four offline checks for the approved configuration. Include a readback of the selected release, independent I/O check, known fixture reference at separate orientations and link-loss recovery. Record who approves each physical check.
  4. Report the backup cutoff, latest recovered cutoff, uncertain units, elapsed restore time and conditions still open. A clean SQLite restore does not exercise physical motion, tool calibration or safeguarding.
