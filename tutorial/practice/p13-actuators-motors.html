Actuators: motors, servos and relays

Make things move. You will drive a DC motor forwards and backwards at any speed through an H-bridge, position a servo with a precise pulse, step a stepper motor, and switch a 12 V load with a relay, all without resetting or damaging your Arduino. Then you will see the same ideas in HVAC damper actuators and door locks.

Why a pin cannot drive a motor

In P11 you learned that a pin can safely give about 20 mA. A small hobby motor draws a few hundred milliamps while running, and often more than 1 A in the instant it starts or when it is stalled (held so it cannot turn). That is 50 times too much for a pin.

There is a second problem. A motor is a coil of wire, an inductor. When you suddenly stop the current through an inductor, its collapsing magnetic field produces a voltage spike that can be tens of volts (you met this "kick" in P08). A third problem: a spinning motor is also a generator, producing a back-EMF that opposes the supply. When the motor starts, there is no back-EMF yet, so the current is limited only by the winding resistance. That is why start-up current is so high.

Istart ≈ V / Rwinding = 6 V / 4 Ω = 1.5 A     Irunning = (V − Vback-EMF) / Rwinding ≈ (6 − 5.2) / 4 = 0.2 A Measure your own motor's winding resistance with the meter (turn the shaft slowly between readings; it changes a bit with brush position). The back-EMF grows with speed, which is why running current is much smaller than starting current.

So we put a driver between the pin and the motor. The pin gives a tiny signal; the driver switches the big current from a separate supply.

Why it works

A motor driver is four transistor switches (usually MOSFETs) controlled by logic inputs. A MOSFET's gate is an insulated plate: a few volts on it, with almost no steady current, opens a low-resistance channel that can carry amps. That is the same "small signal controls big current" idea as the relay and transistor switch of P08, done four times.

The H-bridge: forwards, backwards, brake

One transistor can turn a motor on and off, but only in one direction. To reverse a DC motor you must reverse the current through it. The H-bridge does this with four switches arranged like the letter H, with the motor as the cross-bar.

  • S1 + S4 closed: current flows from the supply, down through S1, left to right through the motor, down through S4 to ground. The motor turns forwards.
  • S3 + S2 closed: current flows right to left through the motor. The motor turns backwards.
  • S2 + S4 closed (both bottom switches): the motor's two terminals are shorted together. The spinning motor acts as a generator into a short, which makes a strong braking force. This is brake.
  • All open: the motor is disconnected and freewheels to a stop. This is coast.
  • S1 + S2 (or S3 + S4) closed: the supply is shorted straight to ground through one side. This is called shoot-through. It destroys the transistors. Driver chips have logic that prevents it.

Bench tip

When a transistor in the bridge turns off, the motor's current must keep flowing for a moment (it is an inductor). Each MOSFET has a built-in "body diode" that gives that current a safe path back to the supply, which is why H-bridge modules do not need the external flyback diode you fitted in P08. Older bipolar bridges like the L298 need external diodes; good modules include them.

Lab 1: a DC motor with the TB6612FNG

The TB6612FNG is a small dual H-bridge chip (two motors) built from MOSFETs. Its datasheet rates it at about 1.2 A continuous per channel (3.2 A short peaks) and a motor supply (VM) up to about 13.5 V, with 2.7–5.5 V logic. Because MOSFETs have low on-resistance, it wastes little voltage and stays cool.

PWM sets the speed

analogWrite(pin, value) on a PWM pin (3, 5, 6, 9, 10, 11 on the Uno) switches the pin fully on and off very fast: about 490 Hz on most pins and about 980 Hz on pins 5 and 6. The value 0–255 sets the duty cycle, the fraction of time it is on. The motor's inductance and its spinning mass smooth the pulses, so it responds to the average: 50% duty from a 6 V supply acts roughly like 3 V. You built the same idea with a 555 in P09.

Vaverage ≈ duty × Vsupply = (value / 255) × Vsupply   e.g. 128/255 × 6 V ≈ 3.0 V The transistors are either fully on or fully off, so they waste very little power. A resistor or linear regulator dropping the voltage instead would turn the difference into heat.
const int AIN1 = 7;    // direction input 1
const int AIN2 = 8;    // direction input 2
const int PWMA = 9;    // speed: must be a PWM pin (marked ~)
const int STBY = 6;    // standby: HIGH = driver enabled

// speed from -255 (full reverse) through 0 (stop) to +255 (full forward)
void setMotor(int speed) {
  if (speed > 0) {                     // forward
    digitalWrite(AIN1, HIGH);
    digitalWrite(AIN2, LOW);
  } else if (speed < 0) {              // reverse
    digitalWrite(AIN1, LOW);
    digitalWrite(AIN2, HIGH);
  } else {                             // zero: both LOW = coast
    digitalWrite(AIN1, LOW);
    digitalWrite(AIN2, LOW);
  }
  analogWrite(PWMA, abs(speed));       // duty cycle 0..255 sets the speed
}

void setup() {
  pinMode(AIN1, OUTPUT);
  pinMode(AIN2, OUTPUT);
  pinMode(PWMA, OUTPUT);
  pinMode(STBY, OUTPUT);
  digitalWrite(STBY, HIGH);            // wake the driver up
}

void loop() {
  for (int s = 0; s <= 255; s += 5) { setMotor(s); delay(40); }     // ramp up forward
  delay(1000);
  for (int s = 255; s >= -255; s -= 5) { setMotor(s); delay(40); }  // slow, stop, reverse
  delay(1000);
  for (int s = -255; s <= 0; s += 5) { setMotor(s); delay(40); }    // back to stop
  delay(2000);
}

Common misconception

"PWM at 50% gives the motor half the voltage, like a dimmer knob." Electrically, the motor sees full voltage half the time and zero the other half. It only behaves like it gets half because its inductance and inertia average the pulses. That is why at low duty a motor may hum but not turn: each short pulse is not enough to overcome friction. Starting at a higher duty and then reducing (a "kick start") fixes it.

The L298N alternative

The red L298N module with a big black heatsink is everywhere in kits. It works the same way logically (IN1/IN2 set direction, ENA takes PWM after you remove its jumper), and it handles up to about 46 V. But it is built from bipolar transistors, which lose about 1.5–2 V each, so roughly 2–4 V in total across the two conducting switches. From a 6 V pack your motor may see only 3–4 V, and the lost power becomes heat. Its on-board 5 V regulator (enabled by a jumper) should only be used with supplies up to about 12 V.

Lab 2: the hobby servo

A servo is a small DC motor, a gearbox, a potentiometer on the output shaft, and a control circuit, all in one box. You do not tell it a speed; you tell it a position. The control circuit compares the position you asked for with the potentiometer reading and drives the motor until they match. This is a closed control loop, the same idea a BMS uses to hold a room at 22 °C.

You send the position as a pulse width, repeated about 50 times per second (every 20 ms). The classic radio-control standard is 1.0 ms for one end, 1.5 ms for centre, 2.0 ms for the other end. Many hobby servos such as the SG90 actually travel further, reaching their end stops at around 0.5 ms and 2.5 ms; the Arduino Servo library maps 0° to 544 µs and 180° to 2400 µs by default.

  1. Wire the servo. Servo wires are usually brown (or black) = GND, red = V+ (about 5 V), orange (or yellow, white) = signal. Signal to D9. Red and brown to a separate 5 V 2 A supply. Join that supply's GND to the Arduino GND.

  2. Upload the sweep sketch below. The horn should sweep smoothly from one end to the other.

  3. Find the real limits. Replace the sweep with myServo.writeMicroseconds(1500); and change the number in steps of 100. Stop increasing when the servo starts to buzz at the end of travel: that is its end stop.

#include <Servo.h>         // built-in library: makes the 50 Hz pulses for you

Servo myServo;              // one Servo object per servo

void setup() {
  myServo.attach(9);        // signal wire on D9 (any digital pin works)
}

void loop() {
  for (int angle = 0; angle <= 180; angle += 2) {   // sweep one way
    myServo.write(angle);   // library converts the angle to a pulse width
    delay(15);              // give the servo time to move
  }
  for (int angle = 180; angle >= 0; angle -= 2) {   // and back
    myServo.write(angle);
    delay(15);
  }
}
Safety: power

A micro servo draws roughly 10 mA when idle but several hundred mA in bursts when it starts to move, and more when stalled against a stop. Powering it from the Uno's 5 V pin on USB is the classic cause of the board resetting every time the servo moves. Use a separate 5 V supply and a common ground. Keep fingers clear of the horn on larger servos: they are strong.

Lab 3: the 28BYJ-48 stepper with a ULN2003

A stepper motor moves in fixed steps. Inside are several coils around a toothed rotor. Energise the coils in a sequence and the rotor follows, one step per change. Because the controller counts steps, you know the position without a sensor (as long as the motor does not skip steps under too much load).

The 28BYJ-48 is a cheap 5 V unipolar stepper (four coil halves with a common centre wire, the red one) with a gearbox of about 64:1. In full-step mode it needs about 2048 steps per output revolution, so each step is about 0.18°. It is slow (about 10–15 rpm at most) but strong for its size. Each coil draws roughly 100 mA at 5 V.

The ULN2003 on its driver board is seven Darlington transistor switches, each able to pull a load to ground. It also contains a flyback diode for each output, connected to its COM pin, so the coils' turn-off spikes are clamped. The four LEDs on the board show which coils are energised.

#include <Stepper.h>       // built-in library

const int STEPS_PER_REV = 2048;    // 28BYJ-48, full-step, after the gearbox

// ULN2003 IN1..IN4 wired to D8..D11.
// The library wants the coils in the order IN1, IN3, IN2, IN4 for this motor:
Stepper stepper(STEPS_PER_REV, 8, 10, 9, 11);

void setup() {
  stepper.setSpeed(10);            // 10 rpm (above ~15 the motor starts to skip)
  Serial.begin(9600);
}

void loop() {
  Serial.println("One turn one way");
  stepper.step(STEPS_PER_REV);     // blocks until finished: about 6 s at 10 rpm
  delay(500);
  Serial.println("One turn back");
  stepper.step(-STEPS_PER_REV);    // negative = the other direction
  delay(500);
}
Bench tip

stepper.step() blocks, like delay() in P11. For projects that must also read sensors, use the AccelStepper library: you call its run() function every pass through loop() and it takes one step only when it is time. It also ramps speed up and down so the motor does not skip.

Lab 4: relay modules for bigger loads

A relay is a switch moved by an electromagnet. A small current through the coil pulls a metal armature, which moves a set of contacts. The contacts are electrically separate from the coil, so a 5 V coil can switch a completely different circuit, such as a 12 V lamp. That separation is called galvanic isolation.

Things to know about cheap relay modules:

  • Many are "active LOW". The relay switches on when IN is pulled LOW, because the input drives an LED inside an opto-coupler from VCC. Check by testing, or look for a jumper marked H/L.
  • JD-VCC jumper. Opto-isolated modules have a jumper linking VCC (the logic side) to JD-VCC (the coil side). Remove it and feed JD-VCC from a separate 5 V supply to keep coil current and noise completely away from the Arduino.
  • Contact ratings. The relay body may say "10 A 250 VAC, 10 A 30 VDC". DC is harder to switch than AC, because a DC arc does not go out by itself at a zero crossing. For inductive DC loads (solenoids, locks, motors), fit a diode across the load and stay well under the rating.
const int RELAY_PIN = 7;
const int RELAY_ON  = LOW;     // most cheap modules switch on when IN is LOW
const int RELAY_OFF = HIGH;

void setup() {
  digitalWrite(RELAY_PIN, RELAY_OFF);  // set the level first so the relay does not click at boot
  pinMode(RELAY_PIN, OUTPUT);          // now drive the pin
  Serial.begin(9600);
}

void loop() {
  digitalWrite(RELAY_PIN, RELAY_ON);   // coil energised: COM connects to NO, lamp on
  Serial.println("Relay ON");
  delay(2000);
  digitalWrite(RELAY_PIN, RELAY_OFF);  // coil off: COM back to NC, lamp off
  Serial.println("Relay OFF");
  delay(2000);
}
Safety: stay at ELV

Relay modules are often sold with photos of them switching a 230 V lamp or power point. Do not do this. The contact rating does not make a hobby module safe for mains: the board's spacing between mains and your 5 V side is often inadequate, there is no enclosure, and mains work in Australia must be done by a licensed electrician. In this course, relays switch only extra-low-voltage loads such as 12 V or 24 V DC lamps, buzzers and lock demos, or 24 V AC from a plug-pack.

Power: separate supplies, common ground, no brown-outs

Motors, servos, steppers and relays all pull large, sudden currents. If they share the Arduino's USB supply, two bad things happen.

  1. The supply voltage dips. The USB port, the cable and the board's fuse all have resistance. A 1 A surge through 0.5 Ω of total resistance drops 0.5 V. If the 5 V rail falls far enough, the microcontroller's brown-out detector resets it (to stop it running unreliably at low voltage). You see your "ready" message again in the Serial Monitor every time the motor starts. Smaller dips can still corrupt readings or crash the program.
  2. Ground bounce and noise. Big current returning through the same thin ground wire as your sensor signals lifts the "0 V" at the Arduino by tens or hundreds of millivolts, in spikes. Analogue readings jump, and logic can glitch.
Why the grounds must be joined

Voltage is always measured between two points. When the Arduino says "HIGH", it means "5 V above my GND". The driver decides HIGH or LOW by comparing its input with its GND. If the two grounds are not connected, the driver has no idea where the Arduino's 0 V is, so the signal is meaningless (and current may find a path through the pins instead). The exception is a deliberately isolated input, such as an opto-coupler with the JD-VCC jumper removed, where the light beam carries the signal and no shared ground is needed.

Put a 100–470 µF electrolytic capacitor across the supply right at each motor driver or servo connector, plus a 100 nF ceramic. The big capacitor supplies the sudden current peak locally, so the peak does not have to travel down long wires from the supply (P07). Mind the polarity: the stripe marks the negative leg.

On the job: actuators in buildings

HVAC damper and valve actuators

In a building, the "motors" a BMS technician deals with most are actuators on air dampers and water valves. A damper actuator clamps onto a damper shaft in a duct and rotates it about 90° to set airflow. A valve actuator turns or lifts a valve stem to set the flow of chilled or hot water through a coil. Inside each is a small motor, a gearbox and a position-feedback circuit: it is a big, slow servo.

A classic commissioning fault: many 24 V AC actuators use the same wire as both the 24 V AC common and the 0–10 V signal reference. If the controller and the actuator do not share that common correctly, or a 24 V AC transformer powers several devices with their wires swapped, the signal is offset or devices are damaged. It is the same "common ground" lesson as your motor driver, at plant scale. Making 0–10 V from an Arduino needs extra parts: PWM, an RC filter (P07) and an op-amp with a gain of 2 (T14), or a ready-made PWM-to-0–10 V module.

Door strikes and magnetic locks

Access control systems switch door locks with a relay in the door controller, exactly like Lab 4. The lock type decides which relay contact you use.

On the job

Security installers wire this every day at 12 V or 24 V DC. You will size the lock power supply (a maglock draws a few hundred mA continuously, so a door full of them adds up), fit the suppression diode with the correct polarity (stripe to +), and check what happens on a power failure and a fire alarm. Building and fire rules require doors on exit paths to let people out in an emergency, which is why fail-safe locks are tied to the fire system. The exact requirements come from the National Construction Code and the fire engineering for each building, so always follow the job's design documents and confirm current rules with the relevant authority. Read more in C06.

In Australia

Lock power supplies and access controllers on site are usually powered from mains through a transformer or switch-mode supply that an electrician has installed. Your work is on the ELV side: the 12/24 V output terminals, the controller relays and the lock cabling. Security installation work also needs a security licence in most states and territories; see C11, and check the current rules with your state's licensing regulator.

Check yourself

Which two switches of an H-bridge must never be closed together, and why?

The two on the same side (S1 with S2, or S3 with S4). Together they connect +V straight to ground through two transistors with almost no resistance: shoot-through. The current is limited only by the supply and the transistors, which overheat and fail.

A 6 V motor driver output runs at analogWrite(…, 64). Roughly what average voltage does the motor see?

64/255 ≈ 25% duty, so about 0.25 × 6 = 1.5 V average. The motor may not even start at that level because of friction.

A servo receives 1.25 ms pulses. With the textbook mapping, what angle is that?

(1.25 − 1.0) / (2.0 − 1.0) × 180° = 45°.

Why does the 28BYJ-48 draw current even when it is not moving?

To hold position, the controller keeps the last pair of coils energised. Two coils at about 100 mA each means about 200 mA continuously. You can switch all four inputs LOW when holding torque is not needed, to save power and heat.

Your relay module turns on when the Arduino pin is LOW. Is it broken?

No. Many modules are active LOW: the input sinks current through the opto-coupler's LED from VCC. Write HIGH for off and LOW for on, and set the pin HIGH before making it an output.

The motor and the Arduino use separate supplies. Why must you still connect their grounds?

Logic levels are voltages relative to ground. The driver compares its input with its own GND. Without a shared ground, the Arduino's 5 V has no defined relationship to the driver's 0 V, so the signal is meaningless. Only deliberately isolated inputs (opto-couplers) can skip it.

A maglock on an exit door: NO or NC contact, and why?

NC. A maglock locks while powered. Through NC, it is powered (locked) while the relay is at rest, and releases when the relay energises (access granted) or when power fails. That fail-safe behaviour lets people exit in an emergency.

Why does a DC motor draw much more current at start-up than when running?

A spinning motor generates a back-EMF that opposes the supply. At standstill the back-EMF is zero, so the current is V/Rwinding. Once spinning, the current is (V − back-EMF)/R, which is much smaller.
