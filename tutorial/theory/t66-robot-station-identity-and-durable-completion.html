T66

Robot station identity, evidence and durable completion

A PLC requests work, a camera inspects it, a fixture provides independent proof, and a robot reports a result. Establish which job each observation describes, then record completion so a repeated message cannot count another part.

Time 50 minutesBefore this T34 · T38 · P161

Watch. Trace a station output from logic to terminal. Identify which part of the lesson keeps its completion identity across a restart. RealPars · Convert a wiring diagram to a PLC program.

Keep four identities available

FieldWhat it identifiesMistake it exposes
Job keyOne commissioned job, for example CELL4:7:42 for cell 4, session 7 and sequence 42A PLC or robot restarts and reuses a sequence number.
Part serial and recipe revisionThe physical workpiece and the settings used to inspect or process itA result refers to the previous part, or to the same part under a different recipe.
Evidence generationThe current set of observations for that job after reviewDelayed proof from before a lost link arrives after a fresh review.
Event ID and sourceOne message from an assigned producer, stable during retransmissionThe same message arrives twice, or a reused event ID carries changed data.

Choose an identity scope that survives controller restarts. A job key remains stable while that job is retried. A genuinely new job gets a fresh key. Physical identification needs a process such as marking, scanning or controlled fixture ownership. A substring match or a copied PLC register cannot establish which piece is in a fixture. Record which component is permitted to make each assertion.

Prove the observation belonged to the same input image

A robot may update its result flag and ID in different transfers. If the PLC reads the new complete flag alongside the previous result ID, that image cannot prove completion. Use a vendor-supported atomic data transfer, or a documented producer-and-consumer scheme that lets the reader detect a partial update. For a versioned buffer, verify that the whole snapshot was copied while the version was stable and marked complete. Confirm the controller’s actual memory ordering and communication behavior with a trace.

Log source timestamp, clock identity and receiving order. A camera’s timestamp of 4,939 ms and a PLC’s 995 ms can both describe one part even if their local clocks began at different times. A job match links the two records. Synchronization or calibrated offsets are necessary before subtracting timestamps to estimate latency. Commit once and keep the evidence together

A result can be recorded and the reply lost. On retry, look up the event ID and compare its payload. Return the stored decision for an identical retry. A different payload under the same ID needs investigation. A unique job key and a unique part serial in the good-part table protect different invariants. In this training station each serial can enter the good count once even if it is registered under a second job.

In a local transactional store, save the evidence decision, the completed-job state and the good-part row in the same transaction. An interrupted write before commit leaves those changes uncommitted. A process that stops after commit can look up the same decision after it returns. Count durable good-part rows so a separate counter write cannot drift from the record. A store still depends on its filesystem, configuration and hardware. SQLite · Atomic commit and storage assumptions · SQLite · Transaction boundaries.

Recover the application and the physical workpiece

A database transaction can make several records agree. The robot and fixture may already have moved by the time the database records the event. When that disposition is uncertain, hold the ordinary process for review, locate the actual part, reconcile the retained controller records and then acquire current evidence against the agreed identity. A reboot test establishes the software behavior. The installed cell’s approved procedure covers safely observing, accessing and recovering equipment.

Check a retry after connection loss

Job CELL4:7:42 committed PART-042 and the reply was lost. A retry with the same event and payload returns the stored commit decision. A new job CELL4:8:42 can use the same numerical sequence 42 under a new session. If it claims PART-042 as a second good part, the physical serial already belongs to the durable count and requires review.
