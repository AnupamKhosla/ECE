Arduino first steps

Install the Arduino software, make an LED blink, read a push button the right way with a pull-up resistor, print to the Serial Monitor, and debounce a button without freezing your program. You will also learn the two rules that keep microcontroller pins alive: respect the logic voltage and respect the current limit.

Time 2–3 hLevel BeginnerKit cost ~A$20–50Theory T15

What a microcontroller board is

A microcontroller is a whole small computer on one chip: a processor (CPU), memory for the program, memory for variables, and many pins that can read or set voltages. It runs one program, forever, from the moment it gets power. There is no operating system and no screen.

The Arduino Uno is a small circuit board built around one microcontroller, the ATmega328P. The board adds the parts you need to use the chip easily: a USB connection for programming, a voltage regulator, a 16 MHz crystal (the clock), a reset button, an LED, and header sockets so you can push jumper wires into the pins.

A genuine Uno costs roughly A$35–50 in Australia. Compatible clones cost roughly A$12–25 and work the same for this course. Most clones replace the USB chip with a cheaper one called the CH340, which sometimes needs a driver (see Troubleshooting).

Common misconception

"An Arduino is a tiny computer like a Raspberry Pi." Not quite. A Raspberry Pi runs Linux, has gigabytes of RAM and boots for half a minute. An Uno has 2 KB of RAM, no operating system, and starts running your program a fraction of a second after power-up. That makes a microcontroller simple, cheap, low-power and very predictable in timing, which is exactly why the controllers inside building plant, alarm panels and door controllers are microcontrollers too.

Install the IDE and talk to the board

The IDE (Integrated Development Environment) is the program where you type code, compile it into machine code, and upload it to the board. Arduino IDE 2 is free from the official arduino.cc website for Windows, macOS and Linux.

  1. Install Arduino IDE 2. Download it from arduino.cc (the "Software" page), install it, and open it. Accept the driver prompts on Windows.

  2. Plug in the board. The green ON LED should light. On a new board the "L" LED often already blinks, because the factory loaded the Blink example.

  3. Select the board. Use the drop-down at the top of the window (or Tools › Board) and choose Arduino Uno. Clones of the Uno also use "Arduino Uno".

  4. Select the port. Tools › Port. On Windows it is a COM port, such as COM3. On macOS it looks like /dev/cu.usbmodem… (genuine) or /dev/cu.usbserial… (CH340 clone). On Linux it is /dev/ttyACM0 or /dev/ttyUSB0. Trick: unplug the board and see which port disappears.

  5. Open Blink. File › Examples › 01.Basics › Blink.

  6. Upload. Click the right-arrow button. The IDE first compiles (translates your code into machine code) and then uploads. The TX/RX LEDs flicker. The output panel ends with "Done uploading" or a message showing how much flash the sketch used.

Bench tip

Half of all "my Arduino is dead" problems are a charge-only USB cable. These cables have power wires but no data wires, so the board lights up but no port appears. Keep one known-good data cable labelled with tape.

Blink: the shape of every sketch

An Arduino program is called a sketch. Every sketch has two functions. setup() runs once after power-up or reset. loop() then runs again and again, forever, as fast as the chip can go.

// Blink: turn the on-board LED on and off, once per second.

void setup() {                      // setup() runs ONCE, after power-up or reset
  pinMode(LED_BUILTIN, OUTPUT);     // make pin 13 (called LED_BUILTIN on an Uno) an output
}

void loop() {                       // loop() runs again and again, forever
  digitalWrite(LED_BUILTIN, HIGH);  // drive the pin to 5 V: LED on
  delay(1000);                      // wait 1000 ms = 1 s (the CPU does nothing else meanwhile)
  digitalWrite(LED_BUILTIN, LOW);   // drive the pin to 0 V: LED off
  delay(1000);                      // wait another second, then loop() starts again
}

The three functions you just used

FunctionWhat it does physically
pinMode(pin, OUTPUT)Switches on the pin's output transistors. The pin can now push current out (HIGH) or pull current in (LOW).
pinMode(pin, INPUT)Output transistors off. The pin only "listens". It draws almost no current (under 1 µA).
pinMode(pin, INPUT_PULLUP)Input, plus an internal resistor of about 20–50 kΩ connected from the pin to 5 V.
digitalWrite(pin, HIGH)Connects the pin to 5 V through a small transistor (a few tens of ohms).
digitalWrite(pin, LOW)Connects the pin to 0 V (GND) through a small transistor.
delay(ms)Waits that many milliseconds. The chip does nothing else useful while it waits.
Try this

Change both delays to 100. Upload. Then try 10, then 5. Somewhere below about 20 ms per flash your eye stops seeing the flicker and the LED looks dimly lit all the time. That is persistence of vision, and it is the idea behind PWM dimming in P09 and P13.

An external LED with a resistor

Now drive your own LED from pin D8. You already know from P02 that an LED needs a series resistor to set its current. The Arduino pin is just a 5 V source that you can switch on and off from code.

  1. Wire it. Jumper from D8 to a breadboard row. 220 Ω resistor from that row to the LED's long leg (anode). LED's short leg (cathode) to the blue GND rail. Jumper from the GND rail to a GND pin on the Uno.

  2. Upload the sketch below. The LED should give a short blip once per second.

  3. Measure. Change the sketch so the LED stays on (digitalWrite(LED_PIN, HIGH); in setup() and an empty loop()). Measure the pin voltage, the LED voltage and the resistor voltage. Fill in the table.

const int LED_PIN = 8;              // the external LED (through 220 Ω) is on D8

void setup() {
  pinMode(LED_PIN, OUTPUT);         // D8 becomes an output
}

void loop() {
  digitalWrite(LED_PIN, HIGH);      // LED on
  delay(200);                       // stay on for 200 ms
  digitalWrite(LED_PIN, LOW);       // LED off
  delay(800);                       // stay off for 800 ms: one short blip per second
}
I = (Vpin − VLED) / R = (4.8 − 2.0) / 220 ≈ 12.7 mA Vpin is a little under 5 V because the pin's output transistor has some resistance (roughly 25 Ω), so it loses a few tenths of a volt at 10–20 mA. VLED is about 2.0 V for red and about 3 V for blue or white. 12.7 mA is well inside the recommended 20 mA per pin.

Reading a push button: floating inputs and pull-ups

Here is the most important idea in this lab. An input pin is a voltmeter with almost infinite resistance. It draws less than a microamp. That is good, because it does not disturb what it measures. But it also means that if nothing firmly connects the pin to a voltage, the pin's voltage is undefined. We say the pin is floating.

A floating pin acts like a tiny antenna and a tiny capacitor. It picks up mains hum from nearby wiring, static from your hand, and switching noise from the next pin. digitalRead() then returns random 1s and 0s. Touch the wire with your finger and the readings change. Beginners often think the board is faulty. It is not; the circuit is incomplete.

The fix is a pull-up resistor: a resistor from the pin to 5 V. When the button is open, no current flows through the resistor (the pin draws nothing), so there is no voltage drop across it, and the pin sits firmly at 5 V: HIGH. When you press the button, it connects the pin straight to GND. Now current flows from 5 V, through the resistor, through the button to GND. The resistor drops the whole 5 V, and the pin sits at 0 V: LOW. The resistor's job is to hold the pin HIGH gently, but lose the argument to the button.

Internal or external pull-up?

The ATmega328P has a pull-up resistor inside every pin, roughly 20–50 kΩ. pinMode(pin, INPUT_PULLUP) switches it on. For a button on a short wire, that is all you need: no extra parts. For long cables or noisy places, add an external 4.7–10 kΩ resistor. A smaller resistor holds the pin more firmly against noise, but wastes more current while the button is held: 5 V / 10 kΩ = 0.5 mA; 5 V / 1 kΩ = 5 mA.

You can also wire it the other way: a pull-down resistor to GND and a button to 5 V, so pressed reads HIGH. The Uno has no internal pull-downs, and wiring buttons to GND is the industry habit (a short to ground is harmless), so this course uses pull-ups.

Build and test the button

  1. Place the button across the centre gap of the breadboard. A 4-leg tactile button has its legs joined in pairs inside. Pins on the same side of the gap that face each other across the button body are usually the switched pair; if in doubt, use the meter's continuity mode: the switched pair beeps only when pressed.

  2. Wire it: one side of the button to D2, the other side to GND. Keep the LED on D8 from before.

  3. Upload the sketch below, then open the Serial Monitor (magnifying-glass icon, top right, or Tools › Serial Monitor). Set its speed to 9600 baud to match Serial.begin(9600).

const int BUTTON_PIN = 2;           // push button between D2 and GND
const int LED_PIN = 8;              // LED + 220 Ω on D8

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);    // input, with the internal pull-up resistor switched on
  pinMode(LED_PIN, OUTPUT);             // LED pin is an output
  Serial.begin(9600);                   // start the serial port at 9600 baud (bits per second)
  Serial.println("Button test ready");  // printed once, so you can see when the board resets
}

void loop() {
  int state = digitalRead(BUTTON_PIN);  // HIGH (1) = not pressed, LOW (0) = pressed
  if (state == LOW) {                   // pressed: the button connects the pin to GND
    digitalWrite(LED_PIN, HIGH);        // so light the LED
  } else {                              // not pressed
    digitalWrite(LED_PIN, LOW);         // LED off
  }
  Serial.println(state);                // print 1 or 0 on its own line
  delay(100);                           // slow down: about 10 lines per second
}

You should see a column of 1s that turns into 0s while you hold the button, and the LED lights while pressed. Now experiment: change INPUT_PULLUP to INPUT, upload, and release the button. Wave your hand near the D2 wire. The readings go random. You have just seen a floating input.

Why it works

An input pin is the gate of a CMOS transistor pair, which is an insulated plate. It reacts to voltage but draws almost no current, so a few picoamps of stray charge can move it. A pull-up gives that charge an easy path to 5 V, so stray charge cannot build up. Inside the chip, the input then compares the pin voltage with two thresholds: above about 0.6 × VCC (3.0 V) it is a guaranteed 1, below about 0.3 × VCC (1.5 V) it is a guaranteed 0, and in between the result is not guaranteed.

The Serial Monitor: your window into the chip

The Uno has no screen, so the Serial Monitor is how you see what your program is doing. Serial.begin(9600) starts the chip's UART (serial port) at 9600 bits per second. The USB–serial chip passes those bits to your computer, and the IDE shows them as text. You will learn exactly how those bits look on a wire in P14.

Bench tip

Opening the Serial Monitor resets an Uno (the USB chip pulses the reset line). That is why "Button test ready" appears again each time you open it. It is normal, and useful: you always see your program start from the beginning.

Debouncing, millis() and why delay() blocks

Contacts bounce

A push button is two pieces of springy metal. When they touch, they bounce apart and back several times before they settle, over roughly 1–10 ms. To you it is one press. To a chip that checks the pin millions of times per second, it is five or ten presses. If your code counts presses or toggles an LED on each press, it will skip and miscount.

Why delay() is a trap

delay(1000) makes the chip spin in a waiting loop for one second. During that second it cannot read buttons, check sensors or update anything else. If you blink an LED with delay() and also want to read a button, a short press during the delay is simply missed.

The professional way is to never wait. Instead, check the clock each time through loop() and act only when enough time has passed. millis() returns the number of milliseconds since the board started, as an unsigned long (a 32-bit number). Your loop() now runs thousands of times per second and can do many jobs "at the same time".

Common misconception

"The Arduino can do two things at once with delay() if I put them in the right order." It cannot. One CPU does one instruction at a time, and delay() fills that time with nothing. The right mental model is a juggler who never holds a ball: loop() quickly visits each job, asks "is it time yet?", does a tiny bit of work if so, and moves on. That pattern is called a non-blocking loop, and it is how real controllers run many control loops at once.

Sketch: blink without delay, while watching a button

const int LED_PIN = 8;                  // external LED
const int BUTTON_PIN = 2;               // button to GND
const unsigned long INTERVAL_MS = 500;  // LED changes state every 500 ms

unsigned long lastToggle = 0;           // millis() value when we last flipped the LED
bool ledOn = false;                     // the LED's current state

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);         // on-board LED will mirror the button
}

void loop() {
  unsigned long now = millis();         // read the clock once per pass
  if (now - lastToggle >= INTERVAL_MS) {  // has 500 ms passed since the last flip?
    lastToggle = now;                   // yes: remember this moment
    ledOn = !ledOn;                     // flip the state
    digitalWrite(LED_PIN, ledOn ? HIGH : LOW);
  }
  // Nothing above ever waits, so this runs thousands of times per second:
  digitalWrite(LED_BUILTIN, digitalRead(BUTTON_PIN) == LOW ? HIGH : LOW);
}

Press the button at any moment: the on-board LED responds instantly, while the external LED keeps blinking on time.

Bench tip

Always write the time test as now - lastToggle >= INTERVAL_MS. Never as now >= lastToggle + INTERVAL_MS. millis() rolls over to zero after about 49.7 days (232 ms). Because unsigned subtraction wraps around too, the first form still gives the right answer across the rollover. The second form fails once every 50 days, which is exactly the kind of bug that appears on a site long after you have left.

Sketch: a debounced toggle switch

Each clean press toggles the LED and prints a count. Try it first with DEBOUNCE_MS set to 0: some presses will count twice or toggle twice. Then set it back to 50.

const int BUTTON_PIN = 2;
const int LED_PIN = 8;
const unsigned long DEBOUNCE_MS = 50;   // the reading must be steady this long to count

int stableState = HIGH;                 // the last state we trusted (HIGH = released)
int lastRawState = HIGH;                // the last raw reading, bounces included
unsigned long lastChangeTime = 0;       // when the raw reading last changed (ms)
bool ledOn = false;                     // LED state
unsigned long pressCount = 0;           // clean presses counted so far

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int raw = digitalRead(BUTTON_PIN);    // may bounce: 0,1,0,1,0 within a few ms
  unsigned long now = millis();

  if (raw != lastRawState) {            // the raw reading changed...
    lastChangeTime = now;               // ...so restart the quiet-time timer
    lastRawState = raw;
  }

  // Accept the new state only if it has been steady for DEBOUNCE_MS
  if ((now - lastChangeTime) >= DEBOUNCE_MS && raw != stableState) {
    stableState = raw;                  // it is real: remember it
    if (stableState == LOW) {           // act on the press only (HIGH to LOW), not the release
      ledOn = !ledOn;                   // toggle the LED
      digitalWrite(LED_PIN, ledOn ? HIGH : LOW);
      pressCount++;                     // count it
      Serial.print("Press number ");
      Serial.println(pressCount);
    }
  }
}
Try this

Hardware debounce: put a 100 nF capacitor from D2 to GND. With the 35 kΩ internal pull-up, the time constant is RC = 35 000 × 100 × 10−9 ≈ 3.5 ms, which smooths the bounce. Now test with DEBOUNCE_MS = 0 again. Fewer double counts? That is the RC charging you met in P07.

5 V and 3.3 V logic levels

The Uno is a 5 V board. Many newer boards are 3.3 V boards: the ESP32 (P18), the Raspberry Pi (P16), and many sensors. Each family has its own idea of what "HIGH" means, and its own maximum.

DirectionSafe?What to do
3.3 V output → Uno inputUsually worksFine for most signals. For noisy or critical lines, use a level shifter.
Uno 5 V output → 3.3 V inputNoUse a resistor divider (e.g. 1 kΩ over 2 kΩ gives 3.33 V) or a level-shifter module.
Two-way lines (I²C)Needs careUse a bidirectional level-shifter module (small MOSFET boards, ~A$3–6).

How not to kill a pin

An output pin is two small transistors: one to 5 V, one to GND. They are designed for signals and LEDs, not power. The ATmega328P datasheet gives an absolute maximum of 40 mA per pin. "Absolute maximum" means "beyond this, damage may happen", not "safe to run here". Design for 20 mA or less per pin, and keep the total for the whole chip under about 200 mA.

Safety: pin killers

1. Output shorted to GND or 5 V. A pin set HIGH and wired straight to GND tries to pass 100+ mA. It gets hot and dies, sometimes in seconds. Put a resistor (220 Ω–1 kΩ) in series with any wire that goes off the board while you experiment.
2. Driving a coil directly. Motors, relays, solenoids and buzzers need more current than a pin can give, and they kick back a voltage spike when switched off. Use a transistor or driver and a flyback diode (P08, P13).
3. Voltage above 5 V or below 0 V on any pin. A 12 V signal on an input destroys it. Use a divider or an opto-isolator.
4. Back-powering. Connecting 5 V to a pin while the board is unpowered feeds the chip through its protection diodes.
Everything in this lab runs from USB at 5 V, well inside the extra-low-voltage (ELV) limit. Never connect an Arduino to mains wiring.

Safety: the 5 V and Vin pins

The 5 V pin on USB power can supply only what your computer's USB port allows (500 mA on USB 2.0, protected by a resettable fuse on the board). The DC jack wants 7–12 V. Never feed 12 V into the 5 V pin: it bypasses the regulator and kills the board.

On the job

The button-and-pull-up idea is everywhere in building systems. A BMS controller's digital input (DI) reads a "dry contact" (a plain switch with no voltage of its own) from a pump's run relay or a filter pressure switch. The controller supplies a small "wetting" voltage through an internal resistor, exactly like INPUT_PULLUP. Alarm panels and door controllers read door reed switches and request-to-exit buttons the same way, and they add end-of-line resistors so the panel can tell "closed", "open", "cut" and "shorted" apart (C04, C06). When a site tech says a DI "is chattering", they mean bounce or a floating input, and you now know both causes.

Check yourself

You wire a button between D4 and GND and use pinMode(4, INPUT). Released, the Serial Monitor shows a mix of 1s and 0s. Why?

D4 is floating. With the button open, nothing connects the pin to any voltage, and an input draws almost no current, so stray charge and picked-up noise set its voltage. Use INPUT_PULLUP (or an external 10 kΩ to 5 V) so it sits firmly at 5 V when released.

With INPUT_PULLUP, does a pressed button read HIGH or LOW, and why?

LOW. Pressing connects the pin directly to GND. The pull-up resistor then has 5 V across it and passes a small current (about 5 V / 35 kΩ ≈ 0.14 mA), but the pin itself is at 0 V. The logic is inverted: pressed = LOW.

An LED with a 100 Ω resistor on a 5 V pin: is that safe for the pin?

I ≈ (4.7 − 2.0) / 100 ≈ 27 mA. That is under the 40 mA absolute maximum but above the 20 mA recommended level, and the pin voltage sags. It is not a good design. Use 220–330 Ω for about 9–13 mA.

Your sketch blinks an LED with delay(2000) and also reads a button. Short presses are often missed. Why, and what is the fix?

delay() blocks: for 2 seconds the CPU only waits and never reaches the digitalRead(). A press that starts and ends inside the delay is never seen. Fix: use millis() timing so loop() never waits and checks the button thousands of times per second.

Why write (now − last) >= interval rather than now >= last + interval?

millis() is a 32-bit unsigned number and wraps to 0 after about 49.7 days. Unsigned subtraction also wraps, so now − last is still the true elapsed time across the rollover. last + interval can overflow to a small number, making the test true or false at the wrong moment.

Can you connect a 5 V Uno output directly to a Raspberry Pi GPIO input?

No. Pi GPIO is 3.3 V logic and not 5 V tolerant; 5 V pushes current through the input's protection diodes and can destroy the pin or the chip. Use a divider (1 kΩ top, 2 kΩ bottom gives 3.33 V) or a level-shifter module.

Why does a smaller pull-up resistor resist noise better?

Noise arrives as tiny currents coupled through stray capacitance. The voltage it causes is roughly that current times the resistance holding the pin. With 10 kΩ instead of 100 kΩ, the same noise current makes one-tenth of the voltage disturbance. The price is more current while the button is pressed (0.5 mA instead of 0.05 mA).

Why does every opening of the Serial Monitor print your "ready" message again?

On an Uno, opening the serial port toggles a control line that the board uses to reset the microcontroller (this is how uploads start automatically). So the sketch restarts and setup() runs again.
